## 0. 핵심 요약 (먼저 읽기)

1. **기획서(접수양식)만 내도 지원 가능.** 시연 영상, GitHub, APK는 선택이지만 가산점이 있음.
2. 1차 합격(20팀)하면 **12월 3~4일 PT 전까지 실제로 동작하는 앱**을 만들어야 함. 에뮬레이터 시연도 인정.
3. 앱은 **Android(API 28+, Kotlin/Java)** 기반의 **Pleos Connect(AAOS)** 앱.
4. **지금 바로 쓸 수 있는 SDK는 Vehicle State(읽기)와 NaviHelper뿐.** 차량 제어(Vehicle Control), TTS, STT, FusedLocation은 개발자 포털에서 **"Coming Soon(준비 중)"** 상태로 표시됨.
5. **시트 진동, 마사지, 햅틱 API는 없음.** 실내 조명(앰비언트 라이트)은 좌석 구역별 색과 밝기 제어 API가 있지만 **제어 계열이라 아직 준비 중**.
6. 내비 SDK의 다음 안내(TBT)는 **회전 종류, 남은 거리(m), 설명 문구** 세 가지뿐. **차로 정보는 없음.**
7. 심사 기준: **차량특화성, 창의성, 기술 활용성(SDK 활용), 사업성(MAU, Retention 등)** + 개발 산출물 가산점.

## 6. 개발 환경

| 항목 | 내용 |
|---|---|
| 플랫폼 | Pleos Connect (현대차그룹 인포테인먼트, **Android Automotive OS 기반**) |
| 요구사항 | Android API 28 이상, Gradle 8.0 이상, Java 또는 Kotlin |
| 에뮬레이터 | Pleos Connect Emulator (Android Studio AVD) — [설치 가이드](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator) |
| 시뮬레이터 | **Pleos Connect Virtual Console** (에뮬레이터 v2.1.0+). `adb forward tcp:8088 tcp:8088` 후 브라우저에서 `http://127.0.0.1:8088/` |
| 개발자 포털 | [Pleos Playground](https://pleos.ai/playground) — 회원 가입 → 프로젝트 생성 → SDK 사용 신청 |

### 6-1. Virtual Console로 시뮬레이션할 수 있는 것
- Vehicle: 차량 알림 표시/숨김
- Motion: 기어, 브레이크, 스티어링 휠 각도, 주행 거리, 핸들 열선
- ADAS: 크루즈 제어 준비·활성 상태, 목표 속도
- Convenience: 도어·창문·트렁크, **시트, 조명**, 와이퍼, 하이패스(ETCS) 시나리오
- Safety: 주차 브레이크, 안전벨트, ABS 등 경고등 켜짐·꺼짐·점멸
- Energy: 주행 가능 거리, 배터리, 충전
- Climate: 공조, 좌석 열선·통풍
- 차량 속도 변경, 주행 이벤트 시나리오 재현, Highway 테마(1인칭/3인칭) 주행 시각화

### 6-2. SDK 제공 상태 (개발자 포털 기준)

| 상태 | SDK |
|---|---|
| **사용 가능 (신청 없이)** | **Vehicle State**, **NaviHelper** |
| **준비 중 (Coming Soon, 신청 불가)** | FusedLocation, TextToSpeech, SpeechToText, **Vehicle Control** |

- 공모전 가이드는 다섯 SDK(Vehicle, NaviHelper, TTS, STT, FusedLocation)를 모두 "사용 가능한 SDK"로 소개하지만, 개발자 포털 문서에는 위처럼 표시되어 있음. **에뮬레이터에서 제어 API가 동작하는지, 공모전 시연에서 써도 되는지는 문의 필요.**
- Vehicle SDK 퍼미션은 Pleos App Market과 **사전 협의·승인된 범위**에서만 선언 가능. 승인 안 된 퍼미션을 선언하면 앱 심사 불통과 (공모전 심사와는 별개로 마켓 탑재 기준).
- 속도, 기어, 외기 온도, 연료 같은 **표준 데이터는 AAOS Car API(CarPropertyManager)**로 받으라고 안내함. Pleos SDK는 시트 제어, 특화 조명처럼 제조사 전용 기능만 제공.
- 차량 모델마다 지원 API가 다르므로 `checkXXXCapabilities`로 확인. NaviHelper는 내비 탑재 차량에서만 동작.

## 7. SDK 상세 (우리 아이디어와 관련된 부분)

### 7-1. NaviHelper SDK (v3.0.5, 사용 가능)

**퍼미션**: 조회는 `pleos.car.permission.NAVI_ROUTE`, 경로 변경은 `NAVI_ROUTE_SEARCH`, 지도 화면 요청은 `NAVI_CUSTOM_MAP`

**주요 메서드**: `getTBTInfo()`, `getCurrentLocationInfo()`, `getRouteStateInfo()`, `getDestinationInfo()`, `getWaypointInfo()`, `requestRoute()`, `requestReRoute()`, `cancelRoute()`, `changeRouteOption()`, `addWaypoint()`, `requestNavigationScreen()`, `requestTrip()` 등

**이벤트 (NaviHelperEventListener)** — 우리에게 중요한 것 굵게
- **`onTBTInfo(List<TBTInfo>)`**: 다음 안내 정보
- **`onCurrentRoadSpeedLimit(Int)`**: 현재 도로 제한 속도, **1초마다** 수신
- **`onCautionPointInfo(List<CautionPoint>)`**: 주의 구간 (종류 + 남은 거리 m)
- `onCameraAlert`, `onCurrentLocationInfo`, `onDrivingInfo`, `onRouteStateInfo`, `onNavigationStatus`, `onRouteStarted`, `onRoutingCompleted`, `onReRouteEnded`, `onRouteCancelled`, `onDestinationArrived`, `onWayPointArrived` 등
- 실제 전달되는 이벤트는 내비 앱 구현과 상태에 따라 다를 수 있음

**TBTInfo (다음 안내)**
```kotlin
data class TBTInfo(
    val type: TurnType,      // 회전 종류
    val distance: Double,    // 다음 회전까지 거리 (m)
    val description: String  // 안내 문구
)
```
- **차로(lane) 정보, 현재 차로, 옮겨야 할 차선 수는 없음.**

**TurnType (주요 값)**
- 일반: `TURN_LEFT`, `TURN_RIGHT`, `TURN_STRAIGHT`, `TURN_KEEP_L/R`(왼쪽/오른쪽 방향), `TURN_SHARP_L/R`, `TURN_UTURN`
- **고속도로: `TURN_ENTER_IC_L/R/C`(진입), `TURN_EXIT_IC_L/R/C`(진출)**
- 지하차도·고가차도: `TURN_ENTER_UNDER_*`, `TURN_AVOID_UNDER_*`, `TURN_ENTER_OVER_*`, `TURN_AVOID_OVER_*`
- 회전교차로: `TURN_ENTER_ROUNDABOUT_02~12`(시계 방향), `TURN_EXIT_ROUNDABOUT`
- 기타: `TURN_DEVIDE_MERGE`(분기·합류), `TURN_TOLL`(요금소), `TURN_ENTER_SERVICEAREA`(휴게소), `TURN_RESTAREA`(졸음쉼터), `TURN_TUNNEL`, `TURN_WAY`(경유지), `TURN_ARRIVE`

**CurrentLocationInfo**: 위도, 경도, 진행 방향(heading), 주소, routeId, currentRouteIndex

**RouteStateInfo**: 경로 안내 중인지(isRouting), naviMode(`ROUTE_GUIDING`, `SAFE_GUIDING`, **`SIMULATION_GUIDING`**, `NOT_WORKING`), routeOption, trafficStatus

**DrivingState**: 목적지·경유지까지 거리(m), 예상 시간(초) 등

**CautionPointType 예**: 사고 다발 구간, 꼬리물기 단속, 버스전용차로, 끼어들기 단속, 내리막, 낙석, 안개, 고속도로 공사, 차로 변경 카메라, 좁은 길, 철길 건널목, 어린이 보호구역, 과속방지턱, 역주행 경고 등

- 제어(set/move)는 `CONTROL_CAR_*` 퍼미션 → **Vehicle Control 계열이라 현재 준비 중**.

**Seat 도메인에 있는 것과 없는 것**
- 있음: 등받이·높이·앞뒤·틸트·헤드레스트·**요추 지지대 앞뒤(LumbarForeAft)·측면 지지대(LumbarSideSupport)** 이동, 메모리 선택, 착석 여부, 안전벨트, 열선·통풍
- **없음: 진동, 마사지, 햅틱**

**Light 도메인 앰비언트 조명 API**
- `setAmbientLightBrightness(area: SeatArea, value: Int)` — 좌석 구역별 밝기
- `setAmbientLightBrightnessColor(area: SeatArea, value: Int)` — 좌석 구역별 색 (32비트 ARGB)
- `setAmbientLightSwitch(area: SeatArea, value: LightSwitch)` — 켜고 끄기
- `setAmbientColorAutoByDriveModeEnabled(Boolean)` — 드라이브 모드 연동 색 자동 (CONTROL_CAR_LIGHTS)
- 문서상 set 계열 대부분이 CAR_LIGHTS로 표기되어 있으나, 포털 분류상 제어 기능이라 사용 가능 여부 확인 필요
- 깜빡임 패턴 API는 없음 (앱이 밝기·색을 반복해서 바꿔야 함)

**TurnSignal**: `getCurrentTurnSignalState()`, `registerTurnSignalState(listener)` — 왼쪽/오른쪽 깜빡이 켰는지 알 수 있음

**SteeringWheel**: `getCurrentSteeringWheelAngle()`, `registerSteeringWheelAngle(listener)` — 조향각(도)

## 8. 주행 중 제한 정책 (앱 설계 시 필수 확인)

- 주행 규제는 차량 속도·기어·브레이크 신호와 지역별 안전 규정으로 적용 (`CarUxRestrictions`)
- **Distraction Optimization(DO)을 선언하지 않은 앱은 주행 중 사용 불가** (주차 중에만 사용 가능)
- 앱 카테고리: Maps/Navigation, Mobility Services, Lifestyle, Entertainment, Business, Music/Audio, Kids, Social/Communication
  - Maps/Navigation: 주행 중 경로 안내, 간결한 지도, **TBT 음성 안내** 등 제한적으로 허용
  - Mobility Services: 주행과 밀접한 차량 관리 서비스, 현재 위치 기반 즉각 정보 등 제한적으로 허용
  - 카테고리를 벗어나는 기능이 있으면 마켓 제출 거부될 수 있음
- 운전자 주의 분산 가이드라인
  - 운전에 필요한 정보는 짧은 시간 안에 이해할 수 있게 간결하게
  - HUD, 클러스터, OSD 영역은 해당 영역 정책 준수
  - 주행 중 동영상, 애니메이션, 움직이는 이미지 최소화
  - 터치 조작 최소화, 음성·물리 버튼 연계
  - **운전에 중요한 오디오 안내는 오디오 포커스 정책에 따라 미디어 일시 중지나 볼륨 조정으로 대응**
- 미디어 앱(동영상, 게임, 브라우저)은 주행 중 사용 불가, 헤드업 알림 게시 금지, **운전과 관련 없는 알림 금지**
- 성능 기준: 터치 응답 0.25초 이내, 앱 실행·콘텐츠 로드 10초 이내, 버튼 반응 2초 이내
- 차량 상태를 바꾸거나 운전 안전에 영향을 주는 API는 별도 심사 기준 적용
- 확인 못 한 문서: 오디오 포커스 개발 가이드, UI Design Guide, UX 규제 세부 사양(피그마 사양서는 비공개)

## 9. 우리 아이디어(결정 지점 알림)에 주는 영향

> 아이디어 정리 문서: `아이디어_결정지점_알림.md`

### 9-1. 되는 것
- **출구 감지**: `onTBTInfo`의 `TURN_EXIT_IC_L/R/C`, `TURN_DEVIDE_MERGE`, `TURN_KEEP_L/R` + `distance`로 "출구까지 몇 미터, 어느 쪽"을 알 수 있음
- **도심 회전**: `TURN_LEFT/RIGHT` + `distance`
- **속도**: AAOS Car API 속도, `onCurrentRoadSpeedLimit`(1초마다), 크루즈 상태
- **운전자가 움직이기 시작했는지**: `TurnSignal`(깜빡이), `SteeringWheel` 조향각 → 출구 쪽으로 차선 변경을 시도하고 있는지 추정 가능
- **교통 상황**: `TrafficCongestionInfo`, `TrafficStatus`
- **시뮬레이션**: `SIMULATION_GUIDING` 내비 모드 + Virtual Console(속도, 조향, 조명 등)로 에뮬레이터 시연 가능성 있음

### 9-2. 안 되는 것
- **시트 진동**: API 자체가 없음 → 핵심 출력을 바꿔야 함
- **현재 차로, 옮겨야 할 차선 수**: 내비 SDK에 차로 정보가 없고, 카메라 영상이나 차로 인식 결과 API도 없음
- **운전자 주의 경고(DAW), 차로 이탈 경고 상태**: 경고등(telltale) API는 있지만 어떤 경고가 포함되는지 확인 못 함

### 9-3. 대안
1. **출력 수단**
   - 1순위: **앱 자체 효과음** (음악을 끄지 않는 짧은 신호음, 남은 거리가 줄수록 빠르게). 오디오 포커스 정책에 맞춰 구현
   - 2순위: **앰비언트 조명** — 출구 쪽 좌석 구역 색을 바꾸는 식. Vehicle Control이 열리면 바로 적용 (지금은 준비 중)
   - 시트 진동: "API가 열리면 적용"하는 확장 제안으로 기획서에만 기재
2. **차선 수 대신 쓸 신호**
   - "출구 2km 전인데 아직 출구 쪽 깜빡이를 한 번도 안 켰다" 같은 **행동 기반 판단**
   - 남은 거리 ÷ 속도 = 남은 시간 → 남은 시간이 기준 이하인데 차선 변경 신호가 없으면 단계적으로 알림
   - 깜빡이 + 조향각 변화로 차선 변경 횟수를 대략 셀 수 있는지는 실험 필요
   - 차로 정보는 "향후 차로 API가 열리면 정확도 향상"으로 확장 제안
3. **기획서 5번(개발 계획)에 쓸 SDK 조합**: NaviHelper(TBT, 제한 속도, 교통) + Vehicle State(TurnSignal, SteeringWheel, DrivingMode) + AAOS Car API(속도) + (확장) Light 제어, TTS
