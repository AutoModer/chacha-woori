## 3. 핵심 메시지 (어디에나 반복)

- **이름**: 차차, 우리
- **한 줄 소개**: "운전 중인 아빠와 집에 있는 가족을, 휴대폰을 보지 않고도 이어 주는 차량 앱"
- **핵심 구조**: **가족이 먼저 다가오고, 아빠는 듣고 "응"만 한다.** 음성으로 차를 조작하는 앱이 아니다
- **슬로건 후보**: "차차, 우리. 가족이 옆자리에 탑니다" / "퇴근길, 가족이 옆자리에 탑니다" / "운전대는 그대로, 가족은 곁에" / "퇴근길, 가족이 먼저 마중 나와요" / "가족이 고른 저녁이 아빠의 목적지가 됩니다"
- **이야기 한 문단**:
  > 아빠는 매일 저녁 한 시간을 혼자 운전해 집에 옵니다. 그사이 대학생 딸은 "아빠 어디야?"를 묻고 싶지만 운전 중일까 봐 전화를 미루고, 엄마는 "올 때 두부 좀"을 말하려다 아빠가 이미 집 앞이라 늦습니다. 아빠는 신호 대기 때 몰래 휴대폰을 봅니다. 퇴근길은 가족과 가장 멀어지는 시간이었습니다. 이제 아빠가 출발하면 딸에게 "아빠 출발했어요"가 가고, 딸은 지도에서 아빠를 보며 "오늘 치킨 먹자" 영상과 함께 치킨집을 보냅니다. 아빠는 "응" 한마디로 치킨집으로 향합니다. 휴대폰을 보지 않아도, 가족이 옆자리에 탑니다.
- **원칙 세 가지**: 가족이 먼저 다가온다 / 아빠는 듣고 "응"만 / 주행 중엔 귀로만

## 4. 접수양식 02 항목별 초안

### 1. 앱 한 줄 소개
> 아빠가 퇴근길에 오르면 가족에게 위치가 공유되고, 가족은 영상·음성 메시지에 저녁 먹을 장소를 붙여 보낸다. 차는 화면 없이 소리로 전하고 "목적지를 바꿀까요?"라고 묻고, 아빠가 "응" 하면 내비 목적지가 바뀐다. 시동·도착 때는 가족 영상 인사를, 들른 장소에서는 가족의 한마디를, 오래 달리면 가족 목소리로 휴식 권유를 들려주는 Pleos Connect 차량 앱.

### 2. 기획 배경 (니즈·불편한 순간, 왜 해결해야 하나)
- **불편한 순간**: 퇴근길 운전 중 가족 메시지가 온 순간 → 무시하거나, 신호 대기 중에 휴대폰을 집어 든다. 가족은 운전 중일까 봐 연락을 미룬다
- **왜 40~50대 가장인가**
  - 출퇴근 운전 시간이 길고 신차 주 구매층 (근거 A1·C2)
  - 운전 중 휴대폰 확인은 사고 위험을 크게 높이고 법으로 금지 (근거 A3·B2·F5)
  - 야근 뒤 밤길·장거리 운전에서 졸음 위험 (근거 A4·A6)
  - 가족 대화 시간이 짧고 그중 아빠와 자녀의 대화가 가장 적다 (근거 A5)
- **기존 해결책의 한계**
  - Android Auto·CarPlay는 메시지를 **읽어 주기만** 한다. "치킨 사 와"를 경로에 넣으려면 운전자가 직접 검색해야 한다
  - 위치 공유 앱은 휴대폰을 상시 추적해 "감시" 느낌. 운전자가 매번 켜야 하는 공유는 운전 중에 못 켠다. 위치를 봐도 가족이 **할 수 있는 게 없다** ("치킨 사 와"는 결국 전화나 카톡)
  - 차량 휴식 안내는 경고음·아이콘이라 익숙해지면 무시하게 된다

### 3. 앱 주요 기능 및 차량 특화 요소
| 기능 | 설명 | 차량 특화 |
|---|---|---|
| **퇴근길 위치 공유** | 퇴근 출발하면 자동으로 공유 시작, 가족에게 "아빠 출발했어요". 가족 앱 지도에 위치와 도착 예정 시간, 도착하면 자동 종료 | 경로 시작·도착 이벤트, 기어, 차량 위치 |
| **장소 붙인 가족 메시지** | 가족이 아빠 위치를 보며 영상·음성 메시지에 장소를 붙여 보냄 ("오늘 치킨 먹자" + OO치킨) | (가족 앱) |
| **소리로 전하고 묻기** | "지은이가 장소를 보냈어요. 영상 메시지가 있어요" → 소리 재생 → "목적지를 OO치킨으로 바꿀까요?" → 아빠 "응". 영상 화면은 정차 때 | 주행 규제(`CarUxRestrictions`), 오디오 포커스, 음성 응답 + 큰 버튼 |
| **경로에 바로 반영** | "응" 하면 내비 목적지 변경(들렀다 가는 곳은 경유지), 가족 앱에 "아빠가 OO치킨으로 가요" | NaviHelper `requestRoute`, 경유지 |
| **시동·도착 인사 영상** | 시동 직후 "아빠 오늘도 화이팅~", 도착 후 "오늘도 고생했어". 기어 P에서만, D로 바꾸면 즉시 멈춤 | 기어, 도착 이벤트, 주행 규제 |
| **장소에 남기는 한마디** | 가족이 장소를 보낼 때 녹음한 한마디를 그곳에 도착·출발하는 순간(기어 P)에 들려줌 ("아빠 순살로 사 와~") | 경유지 도착·출발 이벤트, 기어 |
| **가족 목소리 휴식 권유** | 쉬지 않고 오래 달리면 다음 졸음쉼터·휴게소 전에 가족이 녹음한 말("아빠, 오래 달렸네. 쉬었다 가자")로 권함. 설정은 켜고 끄기만 | 속도·기어, 경로 길목 정보 |
| **가족 앱** | 메시지·음성·장소 보내기, 영상·멘트 녹화, 위치 보기 | (휴대폰 + 서버) |
- **새로운 경험**: 메신저가 "글"을 전한다면, 차차, 우리는 **가족이 먼저 마중 나와 저녁 장소를 건네고, 아빠는 "응" 한마디로 그곳으로 향한다**. 그리고 가장 위험한 순간엔 경고음이 아니라 딸 목소리가 깨운다.
- (보조) 장소를 안 붙인 메시지("치킨 사 와")는 서버 AI가 가족 앱에 장소 검색을 먼저 띄워 준다

### 4. 주요 사용 시나리오
- **사람**: 52세 아빠(회사원, 편도 1시간 운전), 22세 딸 지은(대학생), 50세 아내
- **장면 1 — 아침**: 시동을 켜자 화면에 딸·아내 영상 "아빠 오늘도 화이팅~". 기어 D로 바꾸자 영상이 멈춘다
- **장면 2 — 출발**: 저녁, 아빠가 회사를 나서자 위치 공유가 자동으로 시작 → 집에 있던 딸 휴대폰에 "아빠 출발했어요" → 딸이 앱을 열어 지도에서 아빠 차와 도착 예정 시간을 본다
- **장면 3 — 치킨**: 딸이 OO치킨을 고르고 영상 "아빠 오늘 치킨 먹자~"를 찍어 보냄 → 차: "지은이가 장소를 보냈어요. 영상 메시지가 있어요" → 소리 재생 → "목적지를 OO치킨으로 바꿀까요?" → "응 바꿔 줘" → 내비 목적지 변경, 딸 앱 지도에 "아빠가 OO치킨으로 가요"
- **장면 4 — 치킨집**: 치킨집에 도착해 기어 P → 딸 목소리 "아빠 순살로 사 와~" → 다시 출발하려는 순간 "치킨 챙겼지? 조심히 와"
- **장면 4-1 — 휴식 권유** (주말 장거리로 짧게): 오래 달리다 쉼터가 다가오자 딸 목소리 "아빠, 오래 달렸네. 다음 쉼터에서 쉬었다 가자"
- **장면 5 — 도착**: 치킨을 사서 집 도착, 기어 P → 아내 영상 "오늘도 고생했어", 위치 공유 자동 종료, 딸에게 "아빠 도착했어요"
- **가족의 하루**: "운전 중이야?"를 걱정하던 연락이 "오늘 치킨 먹자"로 바뀐다. 아빠는 퇴근길 내내 가족과 함께 있는 느낌

### 5. 개발 계획 (Pleos Connect 구현, SDK/API 사용 계획)
- **구조**: 차량 앱(Kotlin, Android Automotive) — 포그라운드 서비스가 메시지 수신·낭독·질문·실행·휴식 권유 / 정차 화면(인사 영상, 메시지함, 설정) / 가족 앱(Android, Kotlin) / Firebase(Auth, Firestore, Storage, Cloud Functions: LLM 의도 파악, TTS 음성 파일 생성)
- **SDK·API 사용표**
| 용도 | API | 실측 |
|---|---|---|
| 경로 상태·도착 | NaviHelper `onRouteStarted`, `onDestinationArrived`, `onRouteCancelled` | ✅ |
| 목적지 변경·경유지 추가 | NaviHelper `requestRoute`, `requestRouteWithWaypoints` | ✅ |
| 휴식 권유 판단 | AAOS `PERF_VEHICLE_SPEED`·`GEAR_SELECTION`, NaviHelper 길목 정보(쉼터) | ✅ |
| 장소 한마디 | NaviHelper `onWayPointArrived`, `onRouteStarted` | ✅ |
| 정차·주행 구분 | AAOS `GEAR_SELECTION`, `CarUxRestrictions` | ✅ |
| 메시지·멘트 재생 | Android 오디오 포커스 | ✅ |
| 음성 응답 | Android `SpeechRecognizer` | ⬜ 확인 중 |
| 차량 위치 | Android 위치 API | ⬜ 확인 중 |
| 글 메시지 낭독 | 서버 TTS 음성 파일 (Pleos TTS는 에뮬레이터 오류) | ⬜ |
- **개발 일정**
  - 1차 제출까지: Firebase 연결, 메시지 수신·재생·낭독, 위치 공유·경유지 수락 흐름, 인사 영상, 가족 앱 핵심 화면, 시연 영상
  - 2차 PT까지: 휴식 권유 기준 다듬기, 녹음 자동 보정, 예외 처리 (개인 습관 학습은 이후 검토)
- **한계와 대응 (정직하게)**
  - Pleos TTS 에뮬레이터 오류 → 서버에서 음성 파일로 만들어 재생
  - 졸음을 직접 알 수 있는 API가 없음(운전자 카메라·주의 경고는 실차 특수 권한) → 졸음 감지가 아니라 연속 주행 시간 기준의 **휴식 권유**로 설계
  - 에뮬레이터 주행 시뮬레이션 불가 → Virtual Console로 차량 신호 조작 + 위치 재생
  - 음성인식이 안 되는 환경 → 큰 버튼(예/아니요) 병행
- **정책 대응**: 주행 중 화면 없음·짧은 음성만·질문은 하나, 운전자가 수락해야만 실행, 길 안내는 내장 내비에 요청만(단일 경로 정책), 위치는 수락 시만 공유하고 도착 시 종료, 비공식 API 미사용, 무거운 처리는 서버(CPU 5% 미만)

### 6. 기대효과 및 발전 가능성
- **사용자 가치**: 아빠 — 휴대폰을 보지 않고 가족과 대화, 졸릴 때 가족 목소리 / 가족 — 아빠가 언제 오는지 묻지 않아도 알고, 운전 중인 아빠에게 마음 편히 저녁 약속을 건넴
- **사회적 효과**: 운전 중 휴대폰 사용 감소, 장시간 운전 휴식 유도
- **타깃 분석**: 1차 — Pleos 탑재 신차로 출퇴근하는 40~50대와 가족 / 2차 — 맞벌이 부부, 부모님 운전 가족, 초보 운전 자녀
- **예상 MAU** (근거 수집 후 채움): `Pleos 탑재 차량 수 × 40~50대 주 운전자 비율 × 설치율 × 월 1회 이상 사용률` + 연결된 가족 수
- **Retention 논리**: 출퇴근마다 자동 동작, 퇴근할 때마다 가족에게 "출발했어요" 알림 → 가족이 매일 앱을 연다, 시동 때마다 가족 영상, 가족이 새 영상·멘트를 계속 올림, 사용자가 가족 전체
- **수익 모델**: 기본 무료 / 가족 프리미엄 구독(가족 수, 영상 저장, AI 기능) / 커넥티드 서비스 패키지 / 보험 안전운전 연계(본인 동의, 마케팅 사용 금지 준수)
- **확장**: 가족 목소리 출구·분기점 안내(경로 길목을 남은 시간으로 판단, TBT·깜빡이·조향 실측 완료), 개인 운전 습관 학습으로 휴식 권유 고도화, 출구 직전엔 메시지 낭독 미루기, 가족 목소리 음성 합성, 공조 제안, 부모님 운전 모드·초보 운전 모드

### 7. 참고자료 (가산점)
- 시연 영상: 에뮬레이터(차량 앱) + 실제 휴대폰(가족 앱) 화면 녹화, 7장 시나리오 흐름

## 6. 표현 규칙

- "위치 추적", "감시", "모니터링" 쓰지 않기 → **"아빠가 보내 주는 위치", "공유", "안심"**
- "졸음 감지"라고 쓰지 않기 → **"휴식 권유"**, "차량 기본 안전 기능을 대신하지 않음". "조는 거 아니지?", "일어나!"처럼 의심하거나 다그치는 말 쓰지 않기
- "메신저 앱"이라고 부르지 않기 → **"가족과 이어 주는 차량 앱"** (주행 중 알림 정책 대응)
- AI는 **"가족 메시지를 이해해 물어본다"**까지만. "AI가 차를 조작한다"고 쓰지 않기 (항상 운전자 수락)
- 미확인 숫자는 "보도 기준", "예시"라고 표시하거나 근거 확인 후 사용
- 기능을 나열하지 말고 **장면 하나("아빠 출발했어요" → 딸의 치킨 영상 → "응 바꿔 줘" → 딸 지도에 바뀐 경로)를 깊게**
- 주어는 **가족**으로. "운전자가 음성으로 목적지를 바꾼다"(음성 비서처럼 들림)가 아니라 "가족이 보낸 장소로 아빠가 향한다"
- 개인정보가 02(기획서)·첨부·링크에 나오지 않게 (시연 영상 속 가족 얼굴·이름 포함 주의)

## 7. 예상 질문과 답

| 질문 | 답 |
|---|---|
| Android Auto 메시지 읽기와 뭐가 다른가? | 그건 운전자가 기능을 쓰는 구조다. 우리는 **가족이 먼저 다가온다**. 출발하면 가족에게 알리고, 가족이 보낸 장소를 아빠가 "응" 한마디로 목적지로 삼는다. 그리고 가족 그룹 전용으로 영상 인사·가족 목소리 경고까지 이어진다 |
| 주행 중 메시지 낭독은 운전과 무관한 알림 아닌가? | 지금은 운전자가 **휴대폰을 집어 들어** 확인한다. 우리는 화면 없이, 짧게, 한 번에 하나만 묻는다. 영상·긴 내용은 정차 때. 운전자가 끌 수 있다. 주최 측에 허용 범위를 문의했다 |
| 가족이 차를 마음대로 조종하는 것 아닌가? | 가족은 **제안만** 한다. 경로 변경·위치 공유는 운전자가 "응" 해야만 실행한다 |
| 위치 공유가 감시 아닌가? | 퇴근길 자동 공유는 운전자가 직접 켜 둔 경우만, 퇴근길에만 동작하고 도착하면 자동으로 끝난다. 휴식 권유 판단은 가족에게 보내지 않는다 |
| 졸음을 알 수 있나? | 졸음을 판단하지 않는다. 쉬지 않고 달린 시간·시간대 기준으로 **쉼터 전에 쉬어 가자고 권할 뿐**이다. 연속 일정 시간 이상이면 무조건 한 번 권하는 안전 하한선을 둔다. 개인 습관 학습은 이후 고도화 계획 |
| AI가 메시지를 잘못 이해하면? | 핵심 흐름은 AI 없이 동작한다. 장소는 가족이 직접 고르고, 항상 운전자에게 묻는다. AI는 장소를 안 붙인 메시지를 돕는 보조 기능이고, AI가 실패하면 메시지만 읽고 질문은 생략한다 |
| 음성인식이 안 되면? | 큰 예/아니요 버튼을 함께 둔다. 응답이 없으면 "나중에"로 처리한다 |
| 실제로 구현되나? | 차량 API는 에뮬레이터 실측표, 가족 앱·서버는 실제 동작하는 시연 영상으로 보여 준다 |
| 돈은 어떻게 버나? | 가족 프리미엄 구독, 커넥티드 서비스 패키지, 보험 안전운전 연계(본인 동의) |
