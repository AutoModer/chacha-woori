## 1. 한 줄 요약

음성 안내를 끄고 음악을 들으며 달리는 익숙한 운전자가 출구나 회전 지점을 놓치지 않도록, **평소에는 조용히 있다가 놓칠 것 같은 순간에만** 시선을 뺏지 않는 방식(시트 진동 등)으로 미리 알려 주는 기능.

핵심 개념: **"놓치면 안 되는 결정적 순간에만, 시선을 뺏지 않고 몸으로 알린다."**

---

## 2. 문제 정의 (사용자 경험에서 출발)

1. **고속도로 최면**: 한산한 고속도로에서 멍해지다가 출구를 늦게 알아채고 급하게 차선을 바꾸거나 길을 잘못 든다. 졸음운전은 아니지만 주의력이 떨어진 상태.
2. **음성 안내를 끄는 운전자**: 운전에 익숙한 사람일수록 이미 아는 내용을 반복하는 음성 안내와 음악 줄이기 기능을 귀찮아서 끈다. 그러면 정보가 끊기고 더 멍해져서 중요한 순간을 놓친다. 기능이 많을수록 오히려 위험해지는 역설.
3. **도심 골목 회전**: 처음 가는 번화가에서 골목이 촘촘하면 어느 골목에서 꺾어야 할지 헷갈린다.
   - 내비 화면 확인: 위험하고, GPS가 늦게 반영돼 골목 간격이 짧으면 답답하다.
   - HUD: 남은 거리 숫자가 작아서 읽느라 앞이 잘 안 보인다.

## 3. 해결 방식

### 3-1. 고속도로 모드 (주력)
- 출구까지 남은 거리, **옮겨야 할 차선 수**, 속도로 "이대로면 늦는다"를 계산해서 **미리, 단계적으로** 알린다.
  - 예: 4차로에서만 빠질 수 있는데 지금 2차로 → 차선 두 개 몫만큼 더 일찍 시작.
  - 기준: 차선 하나 옮기는 데 필요한 최소 거리 × 옮겨야 할 차선 수.
- 물리적 한계 기준이라 **멍한 상태를 감지하지 못해도 동작**한다. 주의력 감지(DAW, 실내 카메라)는 있으면 더 일찍 알리는 보조 수단.
- 이미 맞는 차선에 있으면 울리지 않는다.
- 출구에 너무 가까워져 위험하면 알림을 멈추고 **"다음 출구로 다시 안내"**로 바꿔 무리한 끼어들기를 막는다.
- 확장: 교통량(후측방 레이더)이 많으면 시작 시점을 앞당긴다.

### 3-2. 도심 모드 (확장 사례)
- 맞는 골목 **직전에만** 알린다. 첫 번째 골목에서 조용하면 "여기가 아님", 앞 골목을 지나자마자 빠르게 울리면 "이번 골목".
- 지도상 절대 위치가 아니라 **"골목 하나를 지났다"는 사건**을 기준으로 삼아 GPS 오차에 덜 흔들린다.
- 필요 기술: 앞 카메라로 골목 입구 인식 + 바퀴 회전 수로 이동 거리 보정 → 몇 번째 골목인지 세기.

### 3-3. 경보 피로 방어 원칙
- 평소에는 **아무것도 안 함**.
- 조건 세 가지를 모두 만족할 때만 울림: **물리적 한계 기준**, **경로상의 출구나 회전 지점**, **아직 맞는 차선이 아님**.
- 고속도로 한 번 달릴 때 출구는 몇 개뿐이라 반복 경보가 되지 않는다.

### 3-4. 출력 수단
- 1순위: **별도 시트 진동 모터** (안마 기능과 분리)
  - 안마 시트가 없는 차에도 넣을 수 있다.
  - 안마 중에 다른 패턴으로 갑자기 깨우면 더 놀랄 수 있어서 분리한다.
  - 좌우 쿠션에 각각 넣어 방향을 표시한다.
- 시트 진동을 앱에서 못 쓸 경우 대안:
  - 음악을 줄이지 않는 **짧은 신호음** (차선이 많을수록 더 빠르게)
  - 실내 조명이나 HUD 색깔
  - 스마트워치 진동 (공모전 범위인지 확인 필요)
  - 시트 진동은 "차량 API가 열리면 바로 적용"하는 확장 제안으로 둔다.

## 5. 평가

### 강점
- 문제가 진짜이고 누구나 겪어 봤다. 직접 겪은 불편에서 출발.
- 카메라, 지도, 시트 진동 모터, 주의 경고가 현대차에 이미 있어 **연결하는 소프트웨어**로 구현 가능.
- 현대차 시트 진동 하드웨어 특허의 빈칸(쓰임새)을 채우는 제안이라 회사 흐름과 맞다.
- "왜 음성이 아니라 진동이냐"에 대한 답이 분명하다: 음성을 끈 사람에게는 기존 안내가 소용없다. 아이신 방식(음성·화면)과의 차별점.

### 약점 (심사위원이 찌를 곳)
1. **새로움**: 구성 요소가 다 존재. "조합일 뿐 아니냐"에 답 준비 필요.
2. **앱이 시트 진동을 직접 울릴 수 없을 가능성이 큼**: 외부 앱용 차량 SDK는 보통 읽기 위주. 핵심 출력이 막히면 힘이 빠짐.
3. **근거 숫자 없음**: 출구 근처 급차선 변경 사고, 음성 안내를 끄는 비율 등.
4. **효과 검증 없음**: 진동이 음성보다 잘 깨우는지 증명한 게 없음.
5. **자율주행 질문**: "차가 알아서 차선을 바꾸는데 필요하냐" → 현재 운전자 보조 기능은 운전자가 계속 지켜봐야 하고, 그런 기능이 없는 차가 대부분이라고 답변. 확장: 자율주행이 운전을 넘길 때 멍한 운전자를 깨우는 용도.
6. **목적지를 안 찍으면 동작 안 함**: 풀지 않고 **적용 범위로 명시** ("경로가 설정된 경우 동작"). 경로 학습은 향후 확장으로 한 줄.
7. **도심 모드의 위치 정확도**: GPS 오차로 엉뚱한 골목에서 울리면 오히려 위험. 진동은 믿고 바로 꺾게 됨. 카메라로 골목 세기가 승부처.
8. **도심의 다른 경고와 혼동**: 보행자, 자전거, 전방 충돌 경고와 구분 필요.

### 공모전 적합성 (앱 개발 + SDK 연동)
- "버튼 하나 추가"가 아니다. 앱의 핵심은 **언제, 어느 쪽으로, 얼마나 세게 알릴지 판단하는 로직**.
  - 내비 SDK: 경로, 다음 출구나 회전 지점까지 거리, 차로 정보
  - 차량 정보 SDK: 속도, 깜빡이, 현재 차로, 주의력 상태
- 화면이 거의 없는 앱이라는 점이 "운전 중 화면을 안 보게 한다"는 콘셉트와 맞다.
- 아이디어의 진짜 가치는 진동이 아니라 **"평소엔 조용하다가 놓칠 것 같은 순간에만 개입하는 판단 로직"**. 진동은 전달 수단 중 하나.
- SDK로 **지금 구현 가능한 출력**으로 동작을 보여 주고, 시트 진동은 확장 제안으로 두는 것이 안전 ("실현 불가" 감점 방지).
- 편의 기능보다 안전 문제를 푸는 쪽이 심사에서 더 눈에 띈다는 판단에는 동의.
