# 컨셉: 고령 운전자를 위한 "길목 도우미" (가칭)

> ⚠️ 최신 정리는 `길목도우미_통합정리.md`. 이 문서는 컨셉 초안이며, 6장 SDK 상태는 테스트 전 기준이다.

> 작성일: 2026-11-09
> 이전 문서: `논의정리_2026-11-09.md`의 판단 엔진(시간 기준 단계, 해제 조건)을 그대로 쓰고, **사람과 장면**을 고령 운전자로 바꾼 버전
> 이름 후보: 길목 도우미 / 미리길 / 든든길 (확정 전)

---

## 1. 한 줄 소개

**"운전을 계속하고 싶은 부모님을 위해, 헷갈리는 길목을 미리 알려 주고 놓쳐도 당황하지 않게 다시 이끌어 주는 차량용 앱"**

- 방향: 감시나 면허 반납 압박이 아니라 **"계속 운전하실 수 있게 돕는 자립 지원"**

---

## 2. 기획 배경

### 2-1. 숫자로 보는 문제 (보도 기준, 원문 확인 필요)
- 2025년 전체 교통사고 19만 3,889건 중 **65세 이상 운전자가 가해자인 사고 4만 5,873건(23.6%)**
- 전체 사고는 전년보다 1.3% 줄었는데, **65세 이상 가해 사고는 8.3% 늘었음** (도로교통공단 TAAS, 경찰청 통계 인용 보도)
- 고령 운전자의 **인지 반응 능력은 70세 이후 뚜렷하게 떨어지고**, 사고 위험과 더 직접 관련된 건 시력보다 **반응 속도, 상황 인식, 위험 판단**이라는 연구
- 65세 이상에서 반응 시간이 급격히 늘어 현재 설계 기준(2.5초)을 올려야 한다는 연구
- 고령 운전자 700명 설문·주행 모의실험에서 **합류부(진출입 구간 포함)와 터널이 가장 위험한 구간**으로 꼽힘

### 2-2. 사람의 이야기
- 부모님은 병원, 장보기, 친구 모임 때문에 차가 꼭 필요하다. 특히 대중교통이 부족한 지역에서는 운전이 곧 이동권이다.
- 자녀는 걱정되지만 "이제 운전 그만하시라"는 말은 꺼내기 어렵다.
- 부모님이 가장 당황하는 순간은 **처음 가는 길에서 출구나 갈림길을 늦게 알아챈 순간**이다. 급하게 끼어들거나, 갓길에 멈추거나, 길을 잃고 더 긴장한다.
- 기존 내비는 안내가 길고 빠르다. "300미터 앞 우측 방향 서울 방면 진출 후 1킬로미터 앞..." 같은 문장을 한 번에 알아듣기 어렵다.

### 2-3. 왜 차량 앱이어야 하나 (차량특화성)
- 길목 판단에는 **내비 경로(TBT), 속도, 깜빡이, 조향, 크루즈 상태**가 필요하다. 휴대폰으로는 깜빡이·조향·크루즈를 알 수 없다.
- 주행 중에는 화면을 안 쓰고, **정차 중에만** 화면을 쓴다. 차량의 주행 규제(DO) 원칙과 맞는 설계다.

## 3. 대상 사용자

| 구분 | 사람 | 원하는 것 |
|---|---|---|
| 주 사용자 | 65세 이상 운전자, 특히 70대 | 처음 가는 길도 당황하지 않고 가기, 계속 운전하기 |
| 보조 사용자 | 자녀 등 가족 | 걱정 줄이기, 잔소리 대신 도움 주기 |
| 확장 | 초보 운전자, 장롱면허, 렌터카 여행자 | 같은 엔진, 다른 타이밍 |

**페르소나 예시**
- 72세 부모님. 30년 넘게 운전했지만 요즘 반응이 느려진 걸 스스로 느낀다. 다음 주에 처음 가는 대학병원 예약이 있다.
- 45세 자녀. 다른 지역에 산다. 부모님이 고속도로로 병원에 가신다는 말에 하루 종일 마음이 쓰인다.

## 4. 핵심 기능

### 4-1. 미리 알림 (주행 중, 화면 없음) — 핵심
- 기존 판단 엔진: **남은 시간 = 남은 거리 ÷ 속도**로 준비 → 재촉 → 포기 단계
- 고령자 맞춤
  - **더 일찍**: 반응 시간이 길다는 연구를 근거로 준비 시점을 앞당김 (예: 일반 60초 → 90초, 근거 확정 필요)
  - **한 번에 한 가지 행동만**: "오른쪽으로 가세요" 수준의 짧은 말이나 신호. 긴 문장 안내는 하지 않음
  - **노인성 난청 고려**: 낮고 또렷한 신호음, **실내 조명(출구 쪽 좌석 구역 색 변화)**을 함께 사용 → 조명이 원안보다 훨씬 중요해짐
- 해제 조건은 원안 그대로: 출구 쪽 깜빡이, 출구 쪽 조향 변화, 크루즈 해제, 출구 통과·재탐색. 한 번 해제되면 다시 울리지 않음

### 4-2. "괜찮아요" 재안내 (주행 중) — 감성 포인트
- 포기 단계에서 재촉을 멈추고 **차분하게** "괜찮아요. 다음 출구로 안전하게 안내할게요."
- 목적: 놓친 뒤의 당황(급정거, 갓길 정차, 역주행 시도)을 막는 것
- 기존 내비의 "경로를 이탈했습니다" 같은 기계적인 안내와 대비되는 장면으로 PT에서 보여 줌

### 4-3. 오늘의 운전 (정차 후 화면)
- 큰 글씨, 한 화면, **칭찬 중심**: "오늘 길목 다섯 곳을 잘 지나셨어요. 한 곳은 다음엔 조금 더 일찍 알려 드릴게요."
- 점수나 등급은 쓰지 않음 (평가받는 느낌을 주지 않기 위해)

### 4-4. 가족과 나누기 (선택, 운전자가 켜야 동작)
- 도착 알림: "어머니가 병원에 잘 도착하셨어요"
- 원하면 주행 요약 공유 (놓칠 뻔한 곳 수 정도, 위치 기록은 기본 비공유)
- **운전자 본인이 켜고 끌 수 있음**. 감시가 아니라 안심 공유

### 4-5. 길목 기억 (학습)
- 자주 늦게 반응한 출구·갈림길을 기억했다가 다음엔 더 일찍 알림
- 출발 전(정차 중) "오늘 길에 조심할 곳 한 곳" 미리 보기

### 4-6. 가족이 목적지 보내기 (확장)
- 자녀가 휴대폰에서 병원 주소를 보내면 차에서 한 번 눌러 경로 시작 (NaviHelper `requestRoute`)
- 고령자에게 어려운 화면 입력을 줄임
- 휴대폰 앱과 서버가 필요해 1차에서는 화면 시안이나 목업으로만 제시

## 5. 주요 사용 시나리오

**장면 1. 처음 가는 병원 (고속도로 출구)**
1. 출발 전, 화면에 "오늘 길: 오른쪽 출구 한 곳을 미리 알려 드릴게요"
2. 출구 약 90초 전, 낮은 신호음 한 번 + 조수석 쪽 실내 조명이 은은하게 바뀜
3. 반응이 없으면 30초 전부터 신호가 조금씩 빨라짐
4. 부모님이 오른쪽 깜빡이를 켬 → 신호 즉시 멈춤
5. 도착 후 화면에 "오늘도 잘 다녀오셨어요", 자녀에게 도착 알림

**장면 2. 놓쳤을 때**
1. 출구 10초 전까지 반응 없음 → 재촉 중단
2. "괜찮아요. 다음 출구로 안내할게요." 
3. 다음 출구가 다가오면 더 일찍 준비 신호
4. 주행 후 요약: "이 출구는 다음엔 더 일찍 알려 드릴게요"

**장면 3. 자녀의 하루**
- 출근길에 "어머니가 출발하셨어요", 오후에 "도착하셨어요" 알림만 받음. 전화로 "잘 도착하셨어요?" 묻는 대신 "병원 어떠셨어요?"로 대화가 바뀜

## 6. 개발 계획 (Pleos SDK 사용)

| 기능 | SDK / API | 상태 |
|---|---|---|
| 다음 길목 종류·거리 | NaviHelper `onTBTInfo` (`TURN_EXIT_IC_*`, `TURN_DEVIDE_MERGE`, `TURN_LEFT/RIGHT` 등) | 사용 가능 |
| 위험 구간 | NaviHelper `onCautionPointInfo` (사고 다발, 어린이 보호구역 등) | 사용 가능 |
| 제한 속도 | NaviHelper `onCurrentRoadSpeedLimit` (1초마다) | 사용 가능 |
| 도착 | NaviHelper `onDestinationArrived` | 사용 가능 |
| 목적지 설정 | NaviHelper `requestRoute` | 사용 가능 |
| 깜빡이 | Vehicle `TurnSignal` | 사용 가능 (조회) |
| 조향각 | Vehicle `SteeringWheel` | 사용 가능 (조회) |
| 크루즈 상태 | Vehicle `DrivingMode` | 사용 가능 (조회) |
| 속도 | AAOS Car API | 표준 |
| 신호음 | Android 오디오 (오디오 포커스 정책 준수) | 표준 |
| 실내 조명 | Vehicle `Light` `setAmbientLight*` | 준비 중 (확인 필요) |
| 쉬운 음성 안내 | TextToSpeech | 준비 중 (확인 필요) |
| 운전자 주의 경고 | Vehicle `Safety` 경고등 `DRIVER_ATTENTION` | 특수 권한 추정 (확인 필요) |
| 가족 공유, 목적지 보내기 | 별도 휴대폰 앱 + 서버 | 1차는 목업 |

- 앱 카테고리 가정: Mobility Services
- 주행 중에는 화면 없이 백그라운드에서 신호만, 정차 중에만 화면

## 7. 사업성 (초안, 숫자 근거 필요)

- **B2C**: 기본 기능 무료. 가족 공유·길목 기억은 구독 또는 차량 서비스 패키지에 포함
- **보험사 연계**: 고령 운전자 안전운전 특약 할인 (주행 요약 데이터는 본인 동의 시에만)
- **지자체 연계**: 고령 운전자 면허 반납 제도의 대안 또는 보완 (조건부 면허 논의와 연결)
- **확장**: 같은 엔진으로 초보 운전자 모드, 렌터카 모드
- **Retention 논리**: 경로 안내 중이면 따로 실행하지 않아도 자동 동작. 가족 알림이 습관이 됨. 길목 기억은 쓸수록 정확해짐
- **확인할 숫자**: 65세 이상 면허 소지자 수, Pleos Connect 탑재 차량의 고령 소유 비율, 보험사 고령자 특약 사례

## 8. 냉정한 위험 요소

1. **감시·비하로 보이는 위험**: 문구와 화면이 "관리 대상"처럼 느껴지면 공감이 반감으로 바뀜. 칭찬 중심, 본인이 켜는 공유, 점수 없음으로 방어
2. **신호음을 못 들을 수 있음**: 노인성 난청 → 조명이 중요해지는데 조명 제어는 아직 "준비 중"
3. **기준값 근거**: "90초"는 예시. 고령자 반응 시간 연구로 근거를 잡아야 함
4. **실제 고령자 의견 없음**: 부모님이나 주변 고령 운전자 몇 분께라도 직접 물어보고 기획서에 인용하면 설득력이 크게 오름
5. **Pleos 탑재 차량이 신차 위주**: 고령 운전자가 이런 차를 얼마나 타는지 확인 필요. 약하면 "자녀가 사 드리는 차" 시나리오로 보완
